# agent-runtime-mcp v0.2.1

`v0.2.1` prepares the bounded observation history needed for continuous
timeout-based waiting while preserving the generic terminal Channel boundary.
This note is the checked-in metadata for a later formal publication; this
release-preparation Task does not create a tag or GitHub Release.

## Bounded observation continuity

The accepted `snapshot_change` observer retains up to 1,536 change records and
256 KiB of logical UTF-8 serialized event payload per observer. Count and byte
ceilings are enforced independently. Eight observers retain at most 2 MiB of
logical ring payload within the existing 4 MiB retained-state budget; supported
Node/V8 evidence measures the remaining metadata/runtime allowance.

The five-minute cursor TTL is unchanged and is not renewed by waiting. A
`timeout` preserves the supplied cursor and returns it as `next_cursor`, so
callers can continue from the same observation point. Genuine `OBSERVATION_GAP` and `CURSOR_EXPIRED`
conditions remain explicit errors. A fresh observation establishes a new
baseline and cannot acknowledge activity that occurred before it.

`output_idle` remains mechanical `snapshot_change` evidence: it requires a
post-cursor change followed by the requested quiet interval and does not mean
application completion or success. Sampling can miss bytes between samples or
observe redraws. No application completion detection, automatic write retry or
caller-transparent polling is added. `MAX_TOKENS` is unchanged.

## Public surface and compatibility

The public MCP surface remains exactly seven tools:

```text
list_channels
get_channel
read_channel
write_text
send_control
health
wait_channel_event
```

Channel identity, scope enforcement, explicit controls, bounded reads/writes,
and the endpoint lifecycle boundary are unchanged. `package.json` remains
`private: true`; this package is not an npm registry publication.

Issue #38 verification measured eight full 1,536-record observers below the
supported retained-state budget and crossed the former 256-change window on an
isolated Linux/tmux endpoint while preserving timeout cursors and eventually
returning `output_idle`. The previously observed roughly 110-second
end-to-end `read_channel` delay remains unlocalized and is not claimed fixed.
