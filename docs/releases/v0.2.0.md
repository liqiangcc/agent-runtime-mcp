# agent-runtime-mcp v0.2.0

`v0.2.0` adds a bounded terminal-observation wait to the Channel MCP while
preserving the existing Channel boundary and deployment responsibilities.

## What changed

### Bounded Channel event wait

The public surface now includes `wait_channel_event`. Callers first establish
an observation with `get_channel(observe: true)`, then wait from the returned
opaque `next_cursor`. The wait reports only `output_idle`, `timeout`, or a
confirmed same-instance `channel_closed`; terminal output is never treated as
application completion.

Observation uses bounded `snapshot_change` sampling. The server keeps one
shared, lease-bound observer per Channel, validates channel identity and
continuity, and fails closed when the backend cannot prove the required state.
Cancellation and disconnect release waiters through the MCP request signal.

The v0.2.0 limits are fixed server ceilings: `idle_ms` defaults to 1,000 ms
(250..60,000), `timeout_ms` defaults to 30,000 ms (100..60,000), sampling is
250 ms, and observer/waiter/history/capture/retention limits remain bounded.
These limits are implementation ceilings, not guarantees about a web host or
network tunnel.

### Runtime package and release path

The current package/runtime version is `0.2.0`, and archive names derive from
`package.json`. The bundle contains the compiled runtime, production package
metadata and lockfile, runtime/deployment guidance, and the tmux endpoint
keeper; source, tests, development dependencies and repository build tooling
remain excluded.

Formal publication is tag-driven. A `v*.*.*` tag must exactly match
`v${package.json.version}` and have a matching checked-in
`docs/releases/<tag>.md` before the release workflow publishes assets.

## Compatibility boundary

The seven public MCP Tools are:

```text
list_channels
get_channel
read_channel
write_text
send_control
health
wait_channel_event
```

This release does not add Worker, Agent, Task or application semantics, nor
product-owned tmux/session/process lifecycle, raw shell/tmux Tools, or npm
registry publication. `package.json` remains `private: true`.

## Upgrade / installation

Download the release `.tar.gz` and matching `.sha256` asset, verify and extract
them, then install production dependencies:

```bash
sha256sum -c agent-runtime-mcp-v0.2.0.tar.gz.sha256
tar -xzf agent-runtime-mcp-v0.2.0.tar.gz
cd agent-runtime-mcp-v0.2.0
npm ci --omit=dev
```

Prepare the application tmux endpoint outside the MCP, or use the packaged
keeper helper. See the packaged `README.md` for runtime and deployment
configuration.

## Known limitations

- Snapshot sampling cannot capture every byte or redraw between samples.
- tmux identity is a mechanical snapshot and may change under native rename,
  reindex or layout operations.
- Endpoint creation, supervision, recovery, network exposure and transport
  security remain deployment/operator responsibilities.
- The release workflow computes the authoritative checksum from the tagged
  archive; this note intentionally contains no precomputed checksum.
